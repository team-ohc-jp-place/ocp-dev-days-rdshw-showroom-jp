Migration Toolkit for Applications は、クラウド移行に向けたアプリケーションの評価・分析に広く使われてきました。**Developer Lightspeed** (**DLS**) は、MTA の **AI によるコードリファクタリング** 機能です。独立した拡張機能ではありません。開発者の IDE に生成 AI による移行支援を組み込み、モダナイゼーションの進め方を変えます。



[#_the_challenge_of_application_modernization]
== アプリケーションのモダナイゼーションの課題

企業がアプリケーション群をモダナイズする際には、以下の課題があります。

* **セキュリティ** - 古いアプリケーションやフレームワークが、情報漏えいやコンプライアンス違反につながるリスクをもたらします。
* **既存システムの複雑さ** - 古いコードは新しい基盤と互換性がなく、依存関係も密結合で、現在の開発チームが詳しくない場合があります。
* **優先事項の競合** - 限られた資源の中で緊急性とのバランスが必要になり、既存アプリケーションの改善より新機能が優先されがちです。
* **規模と一貫性** - 数百のアプリケーションに同じ変更が必要な企業では、手作業の移行は現実的ではありません。

Developer Lightspeed は、静的解析と生成 AI による簡単な 6 ステップで、アプリケーションの移行を容易にします。

[#_how_developer_lightspeed_transforms_modernization]
== Developer Lightspeed がもたらす変化

**Red Hat Developer Lightspeed for MTA** は、静的解析と **Developer Lightspeed** (生成 AI) を併用した MTA のモダナイゼーションを表します。Visual Studio Code の **MTA 拡張機能** が、静的解析と Developer Lightspeed の両方を提供し、以下の課題に対応します。

* **生成 AI でモダナイゼーションを加速** - 実績のある MTA の静的解析と生成 AI で移行の問題を見つけ、文脈に合った解決策を提案します。IDE 内でコードを提案するため、開発者は画面を行き来せず作業に集中できます。変更の波及にも自動で対処し、リファクタリング中の整合性を保ちます。移行の指標を追跡し、過去の解決策から学習して提案を改善します。

* **開発者が信頼できる修正提案** - ルールに基づく解析で、LLM が探す問題と対処方法を導き、実績のある移行パターンに基づいた提案を行います。変更内容と理由を明確に説明し、開発者が理解できるようにします。IDE のリアルタイムな診断で、実際のコンパイルや実行の問題に対処します。開発者が各変更を確認、承認し、制御と品質を維持します。

* **独自技術のモダナイゼーション** - 組織独自のフレームワークに対する条件と操作をカスタムルールで定義し、AI が固有の技術構成を理解できるようにします。標準ルールの対象外となる独自・社内ライブラリのコード変換も自動化できます。既定の移行パスを組織の知識で拡張し、業務要件に合わせられます。

* **アプリケーション群全体へ展開** - 移行中の変更から学習し、組織の知識を蓄積します。他のアプリケーションでも似たパターンから解決策を予測、生成し、複数アプリケーションを一貫した品質で効率よくリファクタリングできます。

* **開発ワークフローとの統合** - Red Hat Dev Spaces 内で分析と修正を行い、使い慣れた環境で作業できます。問題、提案、コード差分を別のツールに移動せず確認できます。修正後は既存の CI/CD パイプラインでテストとデプロイを自動化し、既存の開発プロセスに組み込めます。

* **AI モデルの選択** - 公開またはセルフホストの LLM を、ファインチューニングせず利用できます。RAG が過去の解決策を知識ベースに保存し、移行履歴に基づいて提案を改善します。OpenAI 互換 API を通じ、Red Hat OpenShift AI (モデル構築・推論サーバー)、Red Hat Enterprise Linux AI (推論サーバー)、vLLM など複数の LLM 基盤に対応します。特定ベンダーに固定されず、性能、コスト、データのプライバシーのバランスを選べます。
