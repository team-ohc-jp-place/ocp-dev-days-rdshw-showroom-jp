[#_what_youll_learn]
== 学べること

このモジュールでは、以下のことを学びます。

* 開発ライフサイクルの各段階にセキュリティのガードレールがどう組み込まれているかを理解する
* Red Hat Dependency Analytics で、パイプラインに到達する前に脆弱性を特定して修正する
* Sigstore のキーレス署名で、自分の ID に基づいてコミットに署名する
* 自動化されたパイプラインによる署名検証、イメージスキャン、ポリシーの適用を確認する
* マージリクエストのチェック、Conforma / Enterprise Contract の検証、署名付き承認を通じてリリースを昇格する
* Sigstore Policy Controller が Namespace レベルで未承認のデプロイを防ぐ仕組みを確認する

[#_who_this_is_for]
== 対象者

このモジュールでは、開発とリリースのプロセスをセキュリティの観点から見ていきます。従来の開発ワークフローに、コードの作成から本番デプロイまで各段階のセキュリティガードレールを追加する方法を理解したい開発者、セキュリティエンジニア、プラットフォームエンジニアを対象としています。

**経験レベル**: 中級。Git、CI/CD パイプライン、コンテナイメージの知識があると役立ちます。

[#_estimated_time]
== 所要時間

このモジュールの完了には約 **60～90 分** かかります。

[#_your_role_and_mission]
== あなたの役割とミッション

あなたは **Parasol Insurance** の開発者です。日常的に使っている、コーディング、コミット、ビルド、デプロイのワークフローには、プラットフォームチームによってセキュリティのガードレールが追加されています。アプリケーションの脆弱性を修正し、強化されたプロセスを通じて変更をリリースしながら、各セキュリティ対策を学びます。

Parasol の CISO 部門は、本番デプロイに以下の要件を定めています。

* 検証済みの開発者 ID に追跡できる **署名付きコミット** からビルドされていること
* 昇格前に **脆弱性スキャン** と **ポリシーチェック** に合格していること
* ビルドパイプラインが正しく実行されたことを示す **署名付きアテステーション** を持つこと
* 本番環境に到達する前に **明示的な承認** を得ていること
* デプロイ時に **アドミッションコントローラ** によって検証されること



[#_the_secured_development_journey]
== セキュアな開発の流れ

このモジュールは、次の一連のストーリーに沿って進みます。

. **プラットフォームとの出会い** -- Developer Hub でセキュアなコンポーネントを確認し、独立したサンドボックスを作成する
. **脆弱性対策のシフトレフト** -- 依存関係の分析により、パイプラインに到達する前に脆弱性を見つけて修正する
. **コミットへの署名** -- Sigstore のキーレス署名で各コミットを自分の ID に結び付ける
. **サンドボックスのパイプライン** -- 署名検証、イメージスキャン、ACS ポリシーのチェックを確認する
. **本番環境への昇格** -- マージ、ビルド、Conforma ポリシーによる検証、リリース承認、デプロイを行う
. **Namespace のセキュリティ** -- Policy Controller が未承認のイメージの実行を防ぐ様子を確認する
