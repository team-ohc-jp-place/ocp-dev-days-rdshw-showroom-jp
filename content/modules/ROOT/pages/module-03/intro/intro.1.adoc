[#_application_connectivity_meets_ai]
=== アプリケーション接続と AI の融合

以前は、システム間のデータフローと AI モデルは別々に扱われていました。今はその状況が変わりつつあります。このワークショップでは、両者を 1 つのプラットフォームに統合します。

連携エンジンがシステム間のデータ移動、変換、複数段階の処理の制御を担当します。接続層はクラスタ外のデータベースへのセキュアなアクセスを提供します。イベントブローカがメッセージングプラットフォームを疎結合にし、イベント駆動の構成にします。AI サービスは、エージェント型の連携フローに大規模言語モデルを提供します。さらに LLM の前段にゲートウェイを配置し、認証とトークン消費量のレート制限を適用します。

ラボを進めながら、これらすべてを使用します。

{empty} +

[#_the_business_scenario]
=== 業務シナリオ

あなたの会社は Parasol Insurance です。顧客が保険申込を送ると、システムが取り込み、データを変換してデータベースに保存し、保険証券を生成します。顧客が契約内容の問題に気付くと、インスタントメッセージングでサポートに連絡します。担当者は調査、修正、保険証券の再生成を行います。

課題は、これらのシステムがつながっていないことです。データベースは別の基盤にあり、メッセージングプラットフォームも分断されています。サポートチームは、複数のシステムを行き来しながら、すべてを手動で処理しています。AI は組み込まれておらず、仮に導入しても管理の仕組みがありません。

各ラボで、これらの課題を 1 つずつ解決します。

{empty} +

B | ② マルチチャネル通信 | 顧客が保険証券の誤りに気付きサポートに連絡しますが、顧客とサポートチームは異なるメッセージングプラットフォームを使用しています。 +
両者を接続して、一方のメッセージがもう一方にも表示されるようにします。担当者は顧客が使うプラットフォームを意識せず、自分のポータルから返信できます。 +
C | ③ AI による問題解決支援 | サポート担当者は契約を検索し、データベースを修正して保険証券を再生成する必要があります。手動操作の代わりに、メッセージングポータル内で AI ボットに話しかけます。 +
連携層が要求を LLM に送り、LLM がデータベースへの問い合わせ、レコードの更新、PDF の再生成などの操作を判断して結果を返します。一連の操作を自然言語で実施します。 +
D | ④ AI 利用量の管理 | AI をワークフローに組み込んだら、呼び出しを許可する相手や消費できるトークン量を管理する必要があります。 +
AI サービスの前段にゲートウェイを配置し、認証とトークンに基づくレート制限を適用します。複数のサービス階層にそれぞれトークン予算を設定し、ある階層の予算を使い切ると次の階層にフォールバックします。

[#_full_technology_stack]
=== 使用するテクノロジースタック

ワークショップでは以下の技術を使用します。これらを組み合わせ、コンテナ化したワークフローの制御、パイプライン全体での信頼性のあるデータ保存、イベント駆動型マイクロサービスの迅速なデプロイを実現します。複雑さを抑えてハイブリッドクラウドの構成をモダナイズし、柔軟でスケーラブルな連携ソリューションを構築できます。

* https://www.redhat.com/en/products/application-foundations[Red Hat Application Foundations,window=_blank]: アプリケーションの構築、デプロイ、運用を支援するコンポーネント群です。このワークショップで使用する以下の製品などが含まれます。

** https://developers.redhat.com/products/red-hat-build-of-apache-camel[Red Hat build of Apache Camel,window=_blank]: 多様なシステムをつなぐ方法を簡素化、標準化する、汎用的なアプリケーション連携ツールキットです。Quarkus と Spring Boot の両方で動作します。

** https://developers.redhat.com/products/streams-for-apache-kafka[Red Hat Streams for Apache Kafka,window=_blank]: Apache Kafka を基盤とし、マイクロサービスや他のアプリケーションが非常に高いスループットと低いレイテンシでデータを共有できる分散基盤を提供します。
+
{blank}

* https://developers.redhat.com/products/openshift-dev-spaces[Red Hat OpenShift Dev Spaces,window=_blank]: OpenShift のワークスペースとブラウザ内 IDE を提供する Kubernetes ネイティブの共同開発ソリューションです。クラウドアプリケーションを迅速に開発できます。

* https://www.redhat.com/en/technologies/cloud-computing/openshift[Red Hat OpenShift,window=_blank]: 任意のハイブリッドクラウド基盤上で、アプリケーションの大規模な構築、モダナイゼーション、デプロイを実現する統合開発プラットフォームです。

* https://www.redhat.com/en/technologies/cloud-computing/openshift-data-foundation[Red Hat OpenShift Data Foundation,window=_blank]: Red Hat OpenShift と統合、最適化された、永続的なソフトウェア定義ストレージと基本的なデータサービスを提供します。

* https://www.redhat.com/en/technologies/cloud-computing/connectivity-link[Red Hat Connectivity Link,window=_blank]: ネットワーク境界を越えたアプリケーション接続を保護し、拡張可能にするソリューションです。異なる環境のサービス間の円滑な通信を実現します。

* https://www.redhat.com/en/technologies/cloud-computing/service-interconnect[Red Hat Service Interconnect,window=_blank]: データベース等をパブリックネットワークに公開せず、OpenShift 上のアプリケーションからクラスタ外のサービスへ安全にアクセスできる接続ソリューションです。
