== Kafka から Rocket.Chat へ

導入で説明したように、_Matrix_ と _Rocket.Chat_ の双方向接続には 4 つのフローが必要です。顧客のメッセージを担当者に届ける経路だけでも、以下の 2 つを使います。

* *フロー 1* — Matrix から Kafka へ _(設定済み)_
* *フロー 2* — Kafka から Rocket.Chat へ ✏️ _(ここで構築します)_

NOTE: 4 つのフローは同じパターンに従い、1 つを構築すれば、他もほぼ同じ方法です。ラボを短くするため、手作業で構築するのはフロー 2 のみで、残りの 3 つは最後に用意して有効にします。

[#_define_kafka_as_the_source_system]
=== Kafka をソースシステムに指定する

最初のステップで、イベントの取得元として _Kafka_ を定義します。

NOTE: 自分の _OpenShift_ Namespace には、利用可能な _Streams for Apache Kafka_ クラスタ (_Kafka_) が用意されています。

1. 次のステップにカーソルを合わせます: pass:[<span style="color: #B0380C;">&#x2757; To do: Kafka</span>] 表示される {nbsp}{btn-replace}{nbsp} ボタンでステップを置き換えます。
1. {ui-filter} に `Kafka` と入力して検索し、_Kafka_ コンポーネントを選択します。
1. _Kafka_ ステップをクリックし、設定パネルを開きます。
1. `All` タブを選択します。
1. 以下の 2 つのプロパティを設定します。
+
上部の {ui-filter} で各項目を素早く検索できます。
+
image::module-03/m3/kaoto-kafka-steps.png[width=100%]
+
`Topic`:
+
[.copypaste.value]
****
myroom
****
+
`Brokers`:
+
[.copypaste.value]
****
my-cluster-kafka-bootstrap:9092
****
+
{empty} +
+
TIP: 設定パネルの外をクリックすると閉じられます。

[#_define_the_filter]
=== フィルタを定義する

_Kafka_ のイベントは、さまざまなシステムに由来します。フィルタがないと、_Rocket.Chat_ のメッセージが _Kafka_ 経由で _Rocket.Chat_ に戻り、ループします。

  * _Rocket.Chat -> Kafka -> Rocket.Chat_ ⟵ ループバック

{blank}

フィルタは、イベントの発生元を確認してこの動作を防ぎます。

[cols="3a,6a"]
|===
|
[.bordered]
[#kaoto-datamapper-configure]
image::module-03/m3/kaoto-filter-config.png[width=100%]

[.overlay]
****
[.target]
kaoto-datamapper-configure

[.numbers]
{x: 43, y: 41, size: 4}
{x: 80, y: 29, size: 4}
{x: 80, y: 86, size: 4}
****
|

1. 次のバーをクリックします: pass:[<code style="background-color: #B0380C; color: white;">&nbsp;To do: Filter&nbsp;</code>]

1. `Required` タブが選択され、既定の式言語が `JQ` であることを確認します。
+
{blank}
+
1. 以下の式をコピーして貼り付けます。
+
{blank}
+
[.copypaste.value]
****
pass:[.source \| test("rocketchat")]
****
+
NOTE: この式は _Kafka_ イベントの `source` を参照し、_Rocket.Chat_ 由来かを判定します。_Rocket.Chat_ 由来のイベントを除外して、ループバックを防ぎます。

|===

[#_test_the_flow_locally]
=== フローをローカルでテストする

_Camel JBang_ でプロセスをバックグラウンド実行します。

{blank}

[.copypaste]
****
labrun k2r --background
****

[TIP]
--
.このコマンドの処理
[%collapsible]
====
`labrun` は内部で Camel JBang を実行するラボ用ヘルパーです。上記は以下の処理に相当します。

* `camel run --name k2r` — `k2r` という名前の連携を実行します
* `--source-dir k2r` — `k2r` ディレクトリからルートを読み込みます
* `--local-kamelet-dir ../support/kamelets` — Rocket.Chat 用を含む独自の Kamelet (コネクタ) を読み込みます
* `--background` — ターミナルで作業を続けられるようバックグラウンドで実行します
====
--

{blank}

[.copypaste]
****
+++camel cmd send k2r --body \
'{
  "user":   "test",
  "source": "test",
  "text":   "test message"
}'+++
****

[TIP]
--
.このコマンドの処理
[%collapsible]
====
* `camel cmd send` — 実行中の Camel プロセスにメッセージを送ります
* `k2r` — 送信先のプロセス名です
* `--body '{...}'` — Kafka イベントを模した JSON です。必要なのは `user`、`source`、`text` だけで、宛先チャネルはマッピングに固定されています
====
--
