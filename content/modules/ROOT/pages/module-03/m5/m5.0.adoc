== ラボ 5 - LLM ガバナンス

Connectivity Link で LLM エンドポイントの前段にガバナンス層を配置し、複数のサービス階層に API キー認証とトークンに基づくレート制限を適用します。

{empty} +

[#_the_scenario]
=== シナリオ

前のラボでは、自然言語でサポートの問題を解決する AI エージェントを構築しました。チャット画面から、データベースへの問い合わせ、レコードの更新、保険証券の再生成を実行できます。

ここに **顧客プロファイル分析** を追加します。担当者が顧客について尋ねると、AI がデータを分析し、整理された要約を返します。分析には 2 つの階層があります。

* **Gold** -- 契約履歴、保険請求履歴、ロイヤルティの状態を詳しく分析します。
* **Silver** -- 最近の契約と基本的なプロファイルを分析します。

Gold は分析が深く、応答も詳しいため、より多くのトークンを消費します。Silver は軽量です。Gold のトークン予算を使い切ると Silver に切り替え、Silver も使い切ると要求の処理を延期する、フォールバックの仕組みを使用します。

その前にガバナンスが必要です。誰が LLM にアクセスでき、各階層でどれだけのトークンを消費できるのでしょうか。制御がなければ、無制限の利用で組織の API 予算を使い切る可能性があります。

このラボでは link:https://www.redhat.com/en/technologies/cloud-computing/connectivity-link[*_Red Hat Connectivity Link_*,window=_blank] を使い、LLM エンドポイントの前段に **ガバナンス層** を配置します。以下の 2 つのポリシーを実装します。

* **AuthPolicy** -- API キー認証とグループ単位の認可で、_誰が_ エンドポイントにアクセスできるかを制御します。
* **TokenRateLimitPolicy** -- 実際のトークン使用量に基づいて、各階層が _どれだけ_ 消費できるかを制御します。

{empty} +

[#_why_connectivity_link]
=== なぜ Connectivity Link を使うのでしょうか

_Red Hat Connectivity Link_ は、このような課題に対応する製品です。link:https://kuadrant.io/[_Kuadrant_ プロジェクト,window=_blank] を基盤とし、AI を考慮したガバナンスを *Kubernetes* に提供します。

* **トークンに基づくレート制限** -- リクエスト数ではなく、実際のトークン消費量で制限します。階層ごとのトークン予算をゲートウェイで強制し、階層型の AI サービスを実現します。
* **コード変更が不要** -- 基盤のレベルでポリシーを適用し、AI エージェントや連携コードの変更は不要です。
* **Kubernetes ネイティブ** -- 標準の CRD として定義し、`oc apply` で適用、Git で保存、PR でレビューできます。専用の管理コンソールやベンダーの制御プレーンは不要です。
* **組み合わせ可能** -- 一方で ID を抽出し、もう一方がその ID を階層別のトークン予算に使うなど、宣言的に重ね合わせられます。

これらは、Connectivity Link が _Kubernetes Gateway API_ 標準を基盤としていることで実現します。ポリシーを設定する前に、このモデルを確認します。

{empty} +

[#_the_gateway_api_model]
=== Gateway API のモデル

Connectivity Link は、_Kubernetes_ のトラフィック経路を管理する標準である _Kubernetes Gateway API_ の上に構築されています。このモデルを理解すると、後の演習が分かりやすくなります。

主な構成要素は以下のとおりです。

* **GatewayClass + Gateway** -- プラットフォームチームが所有し、通信が _どのように_ クラスタに入るかを定義します。設定済みです。
* **HTTPRoute** -- プラットフォームまたは開発チームが所有し、通信が _どこへ_ 向かうかを定義します。このラボでは LLM API が宛先です。
