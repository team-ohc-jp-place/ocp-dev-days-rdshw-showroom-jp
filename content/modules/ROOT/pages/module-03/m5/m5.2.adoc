[#_auth_policy_powered_by_connectivity_link]
=== Connectivity Link による認証ポリシー
概念と構成を理解したので、LLM エンドポイントを保護します。HTTPRoute (`ai-proxy-route`) に **AuthPolicy** を付与し、キーによる認証を強制します。有効な API キーを持つ認可済みのユーザーだけが LLM にアクセスできるようにし、次のレート制限で使う ID 情報も抽出します。

NOTE: このワークショップでは簡単な API キー認証を使いますが、_Connectivity Link_ は JWT、OAuth2 など多様な認証方式に対応します。

{empty} +

[#_understanding_the_user_secrets]
=== ユーザー用 Secret を理解する

2 つの API キー用 Secret は *作成済み* です。両方のポリシーがラベルとアノテーションを参照するため、その構造を確認します。

**Silver 階層のユーザー:**
[source,yaml,subs="attributes"]
----
apiVersion: v1
kind: Secret
metadata:
  name: trlp-tutorial-api-key-silver-{user-username}
  namespace: kuadrant-system
  labels:
    authorino.kuadrant.io/managed-by: authorino
    app: my-llm-{user-username}
  annotations:
    kuadrant.io/groups: silver
    secret.kuadrant.io/user-id: {user-username}
stringData:
  api_key: [some_random_string]
type: Opaque
----

主なフィールドは以下のとおりです。

* `authorino.kuadrant.io/managed-by: authorino` -- _Connectivity Link_ の認証エンジンである _Authorino_ が管理する Secret と示します。
* `app: my-llm-{username}` -- AuthPolicy が有効な API キーを検索するためのラベルセレクタです。
* `kuadrant.io/groups: silver` -- Silver グループへの所属を表し、適用するレート制限の階層を決めます。
* `secret.kuadrant.io/user-id: {user-username}` -- 一意のユーザー ID で、ユーザー別レート制限のカウンターキーに使用します。

{empty} +

**Gold 階層** の Secret は同じ構造で、以下だけが異なります。

* `kuadrant.io/groups: gold`

// == Securing the LLM with Authentication

// Now that you understand the architecture and the setup, it's time to lock down the LLM endpoint so that only authorized users in the organization can access it. You will create an **AuthPolicy** that is applied to the `ai-proxy-route` HTTPRoute and enforces:

// 1. **API Key Authentication** -- Only requests with a valid Bearer token (matching a known secret) are allowed.
// 2. **Group-based Authorization** -- Only users belonging to the `lite` or `pro` groups can access the API.
// 3. **Identity Extraction** -- The user's group and user ID are extracted from the secret's annotations and passed downstream for use by the TokenRateLimitPolicy that we will create in the next section.

[#_review_and_apply_the_authpolicy]
=== AuthPolicy を確認して適用する

AuthPolicy を確認し、以下のコマンドをターミナルに貼り付けて *適用* します。

[.copypaste]
****
oc apply -f - <<EOF
apiVersion: kuadrant.io/v1
kind: AuthPolicy
metadata:
  name: ai-proxy-auth
  namespace: {user-username}-devspaces
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: ai-proxy-route
  rules:
    authentication:
      api-key-users:
        apiKey:
          selector:
            matchLabels:
              app: my-llm-{user-username}
        credentials:
          authorizationHeader:
            prefix: Bearer
    response:
      success:
        filters:
          identity:
            json:
              properties:
                groups:
                  selector: auth.identity.metadata.annotations.kuadrant\.io/groups
                userid:
                  selector: auth.identity.metadata.annotations.secret\.kuadrant\.io/user-id
        headers:
          authorization:
            plain:
              selector: auth.identity.metadata.annotations.secret\.kuadrant\.io/upstream-token
      unauthenticated:
        headers:
          "content-type":
            value: application/json
        body:
          value: |
            {
              "error": "Unauthenticated",
              "message": "Invalid or missing API Key."
            }
      unauthorized:
        headers:
          "content-type":
            value: application/json
        body:
          value: |
            {
              "error": "Forbidden",
              "message": "Access denied. Your account does not have the required permissions (gold/silver)."
            }
    authorization:
      allow-groups:
        opa:
          rego: |
            groups := split(object.get(input.auth.identity.metadata.annotations, "kuadrant.io/groups", ""), ",")
            allow { groups[pass:[_]] == "gold" }
            allow { groups[pass:[_]] == "silver" }
EOF
****

このポリシーの主なフィールドは以下のとおりです。

* `namespace: {user-username}-devspaces` -- 自分の Namespace にポリシーを作成します。
* `name: ai-proxy-route` -- HTTPRoute `ai-proxy-route` に一致するすべての要求を、認証の対象とします。
* `app: my-llm-{user-username}` -- このラベルを持つ _Kubernetes_ Secret から有効な API キーを探します。
* `prefix: Bearer` -- `Authorization` ヘッダーに API キーを要求します。
* `kuadrant\.io/groups` -- 一致した Secret のグループ情報を抽出し、応答フィルタの `groups` として公開します。
* `secret\.kuadrant\.io/user-id` -- ユーザー ID のアノテーションを抽出し、`userid` として公開します。
* `rego` -- `gold` または `silver` グループのユーザーだけを許可する OPA (Open Policy Agent) ルールです。
