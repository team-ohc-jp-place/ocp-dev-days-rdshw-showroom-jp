== トークンのレート制限

次はトークン消費量を制御します。**TokenRateLimitPolicy** は、従来のようなリクエスト数ではなく、LLM の応答で実際に *使用されたトークン* を追跡します。

レート制限ポリシーは、AI の機能とコスト・リソースの管理を組み合わせます。この演習では Customer Profile Tool がトークン予算に応じて分析の階層を選ぶ仕組みを確認します。

LLM の呼び出しは計算資源を消費し、詳しい分析ほど多くを必要とします。AI の利用拡大に伴い、コストと基盤の容量管理が重要になります。レート制限で、サービス全体のトークン使用量を制御できます。

Customer Profile Tool は、単なる拒否だけでなく、段階的にサービスを縮小して継続する方法を採ります。まず *Gold* で分析し、予算を使い切ると *Silver* に切り替え、低コストで有用なプロファイルを提供します。両方を使い切った場合のみ、要求を拒否します。

[#_apply_and_verify_the_tokenratelimitpolicy]
=== TokenRateLimitPolicy の適用と確認

TokenRateLimitPolicy は、ゲートウェイのリソースです。階層別のトークン予算を定義し、アプリケーションとは独立してゲートウェイで強制します。

. _DevSpaces_ の kbd:[+] アイコンで新しいターミナルのタブを開きます。テスト用に、_Camel_ が動作中のタブは残してください。
+
[#terminal-tab]
image::module-03/m5/devspace_terminal_new_tab.png[Dev Spaces のターミナル,width=70%]
+
[.overlay]
****
[.target]
terminal-tab

[.arrows]
{x: 38, y: 67, rot: -45, size: 3}
****
+
{empty} +
+
NOTE: ポリシーは基盤レベルで動作するため、エージェントの実行中に適用でき、再起動は不要です。
+
{empty} +

. 階層別のトークン予算を確認し、自分の Namespace にポリシーを適用します。
+
--
各階層のコストに応じて、2 つの予算を定義しています。

* *Gold* — 詳しい分析で計算コストが高いため、予算は少なく、補充までの時間も長く設定します。
* *Silver* — 軽量で計算コストが低いため、予算は多く、より短時間で補充されます。
--
+
{blank}
+
以下の TokenRateLimitPolicy を確認し、新しいターミナルに YAML を *貼り付けて適用* します。
+
{blank}
+
[.copypaste]
****
oc apply -f - <<EOF
apiVersion: kuadrant.io/v1alpha1
kind: TokenRateLimitPolicy
metadata:
  name: openai-token-limits
  namespace: {user-username}-devspaces
spec:
  targetRef:
    group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: ai-proxy-route
  limits:
    gold:
      rates:
        - limit: 50
          window: 4m
      when:
        - predicate: |
            auth.identity.groups.split(",").exists(g, g == "gold")
      counters:
        - expression: auth.identity.userid
    silver:
      rates:
        - limit: 500
          window: 2m
      when:
        - predicate: |
            auth.identity.groups.split(",").exists(g, g == "silver")
      counters:
        - expression: auth.identity.userid
EOF
****
+
`gold` は少ない予算と長い期間、`silver` は多い予算と短い補充期間になっていることを確認します。
+
[IMPORTANT]
====
TokenRateLimitPolicy は AuthPolicy に依存します。参照する `auth.identity.groups` と `auth.identity.userid` は、AuthPolicy の `response.success.filters` で設定されます。AuthPolicy がないと、評価に必要な ID 情報を得られません。
====
+
{empty} +

. TokenRateLimitPolicy を確認します
+
Dev Spaces のターミナルで以下を実行し、作成されたことを確認します。
+
[.copypaste]
****
oc describe tokenratelimitpolicy -n {user-username}-devspaces \
| grep -iE "Name:|target|gold:|silver:|limit:|window:|type:|status:"
****
+
[TIP]
--
.このコマンドの処理
[%collapsible]
====
* `oc describe tokenratelimitpolicy` — リソースの全詳細を表示します
* `-n {user-username}-devspaces` — 自分の Namespace を指定します
* `grep -iE "Name:|target|..."` — 名前、対象、制限、状態などの主要項目に出力を絞ります
====
--
+
ポリシーが存在し、正しい HTTPRoute を対象として強制適用されていることを示す、以下のような出力を確認します。
